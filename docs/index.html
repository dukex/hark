Keep your coding agent in the loop

hark connects Claude Code to GitHub, Slack, Discord, Jira, Linear, Datadog and Todoist. When a reviewer asks for changes, CI breaks, a teammate pings you or an alert fires, your agent hears about it, tells you what it means and offers to handle it.

MCP lets your agent ask. hark lets it hear.

Tools and MCP servers answer when your agent calls them, so it learns about a review only if it thinks to look. hark runs as a background monitor instead: each new event reaches the agent on its own, about a minute after it happens, and the agent works out what it means for you.

Without hark

You find out when you go and look.

  1. 10:05Carol requests changes on #15
  2. 10:12CI fails on main
  3. 10:31Ana asks for you in #deploys
  4. 11:40You check GitHub and Slack and find all three
Noticed up to 95 minutes later

With hark

Your agent tells you as it happens.

  1. 10:05Carol requests changes on #15
  2. 10:06Explains what the review asks for
  3. 10:12CI fails on main
  4. 10:13Names the failing job and offers to read the logs
  5. 10:31Ana asks for you in #deploys
  6. 10:32Tells you what she needs
Each one reaches you in about a minute

What your agent does with each event

One prompt tells the agent what each kind of event means for you. These are its defaults, and editing the prompt changes them.

  • GitHub

    Acts on review feedback

    Reads the review and its inline comments and tells you what the reviewer asks for, so you can decide what to change.

    pr.changes_requested
  • GitHub

    Catches broken builds

    Names the workflow and the branch that failed, and offers to read the logs.

    ci.failed
  • Slack

    Relays mentions and DMs

    Tells you who wrote, where and what they ask for. It never answers in Slack for you.

    slack.mentioned
  • Datadog

    Flags alerts on what you own

    Reports monitors that go into Alert or No Data on your services, and tells you when they recover.

    datadog.alert
  • Jira

    Brings in new work

    Tells you right away when an issue is assigned to you or a comment mentions you.

    jira.assigned
  • Todoist

    Reminds you what is due

    Mentions each task due today, once, so nothing slips while you are heads down.

    task.due

Set up with one prompt

Claude Code does the installing. You give it access to your accounts and paste the prompt, which works in Copilot CLI too.

Connect your accounts

Run hark login <service> in your terminal for each service you use. It asks for what the service needs, without echoing tokens, and keeps them in your system keychain, never in your shell profile. GitHub needs nothing more if you are logged in with gh.

GitHub
GITHUB_TOKEN, or the token from gh auth token
Slack
SLACK_TOKEN, the user token of a Slack app you create with the search:read user scope
Discord
DISCORD_TOKEN, the token of a bot you create with Message Content Intent and add to your servers, and DISCORD_USER_ID, your own user ID
Jira
JIRA_URL, JIRA_EMAIL and JIRA_API_TOKEN
Linear
LINEAR_API_KEY, a personal API key from Settings, Security & access
Datadog
DD_API_KEY and DD_APP_KEY, plus DD_SITE if your site is not datadoghq.com
Todoist
TODOIST_API_TOKEN

Paste the prompt into Claude Code

It tells the agent how to install and run hark, what to do with each kind of event, and to ask you before it replies, reacts, closes, mutes or changes anything.

Watch my Datadog, Discord, GitHub, Jira, Linear, Slack and Todoist activity with hark while we work.

1. If `hark` is not on PATH, install it with
   `curl -fsSL https://hark.dukex.sh/install | sh`.
   Then run `hark help` and read it: it describes every line hark prints,
   every flag and how to restart a monitor without losing events.
2. Run `hark doctor`. If a provider shows `✗`, tell me what failed. Only start
   monitors for providers whose checks all pass. To set up one that is not
   configured, tell me to run `hark login <provider>` in my own terminal;
   never ask me to paste a token here.
   Start a background monitor running `hark github 2>&1`, described as
   "GitHub activity on my issues and PRs", with the longest timeout allowed.
   When it expires, start it again. If more than an hour passed since it
   stopped, add `--since <time of its last line that is not an error>`, so
   nothing in between is lost. If your tool has no monitor but wakes you
   when a background command exits (Copilot CLI does), add `--exit-on-event`
   and run it as a detached background command instead: it exits after
   printing new events, so handle them and start it again right away, with
   `--since <time of its last line that is not an error>`. With neither, run
   it in the background and read its output every few minutes.
3. Each line is one event:
   `<time> github <kind> <repo>#<number> @<actor> [watching] "<text>" <url>`.
   - `issue.commented` / `pr.commented` without `watching`: someone commented on
     my issue or PR. Read the whole comment (`gh issue view` or `gh pr view
     --comments`), tell me what it asks for, and if it is about the work in this
     session, propose the change.
   - `pr.reviewed`, `pr.changes_requested` without `watching`: someone reviewed
     my PR. Read the review and its inline comments (`gh pr view --comments`
     and `gh api repos/<repo>/pulls/<number>/comments`) and tell me what it asks for.
   - `pr.approved`, `issue.closed`, `pr.closed`, `pr.merged`, `pr.opened`: tell me
     in one line.
   - Lines with `watching`: threads I follow but did not open. Mention them only
     if they @mention me or touch what we are working on.
   - `*.updated`: other activity, the text is GitHub's reason (for example
     `review_requested`). Tell me about review requests.
   - `ci.failed`: a workflow failed. Tell me which one and on which branch, and
     offer to read the logs (`gh run list --repo <repo> --branch <branch>`).
   - `ci.approval_requested`: someone is waiting for me to approve a deploy. Tell me.
   - `ci.succeeded`, `ci.cancelled`, `ci.skipped`: stay quiet unless I am
     waiting for that workflow.
   - `error`: hark keeps retrying and prints a repeated error only once. Tell me
     what failed.
   - A line starting with `hark:` means hark stopped. Show it to me.
4. If doctor shows jira working, start another monitor the same way with
   `hark jira 2>&1`, described as "Jira activity on my issues". Jira, Linear,
   Slack, Discord, Todoist and Datadog resume where they stopped on their own,
   so re-arm them without `--since`:
   - `jira.mentioned`, `jira.assigned`: tell me right away.
   - `jira.commented`: tell me what it asks for.
   - `jira.transitioned`: tell me in one line.
   If doctor shows linear working, start `hark linear 2>&1`, described as
   "Linear inbox":
   - `linear.mentioned`, `linear.assigned`: tell me right away.
   - `linear.commented`: tell me what it asks for.
   - `linear.transitioned`: tell me in one line.
   - Other `linear.*` kinds: stay quiet unless they touch this session's work.
   If doctor shows todoist working, start one more with `hark todoist 2>&1`,
   described as "Todoist activity":
   - `task.due`: remind me of what is due today, once.
   - `task.commented`: tell me what the comment says.
   - `task.created`, `task.completed`, `task.rescheduled`: stay quiet unless
     the task is about the work in this session.
   If doctor shows slack working, start `hark slack 2>&1`, described as
   "Slack mentions and DMs":
   - `slack.mentioned`, `slack.dm`: tell me who wrote, where, and what they
     ask for. Do not answer in Slack.
   If doctor shows discord working, start `hark discord 2>&1`, described as
   "Discord mentions and replies":
   - `discord.mentioned`, `discord.replied`: tell me who wrote, in which
     server, and what they ask for. Do not answer in Discord.
   If doctor shows datadog working, ask me which services or teams I own and
   start `hark datadog --filter '<that>' 2>&1`, described as "Datadog
   monitors": without a filter it reports every monitor in the organization.
   - `datadog.alert`, `datadog.no_data`: tell me right away, with the monitor.
   - `datadog.warn`: tell me in one line.
   - `datadog.recovered`: tell me in one line if I was told it was down.
   If I ask to watch only some repos, projects, channels, tasks or services,
   pass `--filter` with the provider's own syntax (see the hark README).
5. Never reply, react, close, mute or change anything on GitHub, Jira, Linear,
   Slack, Discord, Todoist or Datadog without asking me first.

Safe to leave running all day

hark reads and reports. Your agent asks before it acts.

  • Asks before it acts

    The prompt tells your agent never to reply, react, close, mute or change anything in your accounts without asking you first.

  • Reads, with one exception

    hark only reads your accounts. It marks the GitHub notifications it reports as read, so none reaches your agent twice.

  • Nothing to host

    No server, no webhooks, no sign-up. hark runs on your machine with your tokens and talks only to the services you connect, and to GitHub to update itself.

  • Restarts lose nothing

    Every service except GitHub continues from a saved cursor. GitHub continues from the time your agent passes to --since.

  • Hears only what you own

    Narrow each service in its own syntax, from GitHub search qualifiers to JQL, so your agent hears about your work and nobody else's.

  • Updates itself

    On every start hark checks for a newer release, verifies its checksum and restarts on it. Set HARK_NO_UPDATE=1 to turn that off.

Every pull request to hark runs its tests with a 100% coverage check, golangci-lint and shellcheck.

One line per event, written for agents

Under the hood, hark prints each event as one line with fixed fields, and hark help explains every line to the agent. Select a field to find it in the line.

2026-11-23T10:10:00Z github pr.commented acme/lib#40 @frank watching "rebase?" https://github.com/acme/lib/pull/40#issuecomment-70

One monitor per service

Run one hark per service. Each checks every minute and reports only what is new since its last line.

GitHub

issue.commentedpr.commented
Someone comments on your issue or PR, or one you watch.
pr.reviewedpr.approvedpr.changes_requested
Someone reviews a PR, with the review and how many inline comments it has.
issue.closedpr.closedpr.mergedpr.opened
Someone, or you, opens, closes or merges.
ci.failedci.succeededci.cancelledci.skipped
A workflow run you get notified about finished.
ci.approval_requested
A deploy is waiting for your approval.
issue.updatedpr.updated
Anything else, with GitHub's reason, like review_requested.
Good to know

Marks each notification as read once it prints it, so nothing comes twice. After more than an hour off, pass the last line's time to --since.

Watch less, with notification search qualifiers --filter 'org:acme -is:ci'

Slack

slack.mentioned
Someone @mentions you, in a channel or a DM.
slack.dm
Someone writes to you in a DM or group DM.
Good to know

Finds messages with Slack search, so one shows up once Slack indexes it, usually within a minute. Skips your own messages and continues from a saved cursor.

Watch less, with Slack search modifiers --filter '-in:#random -in:#alerts'

Discord

discord.mentioned
Someone @mentions you in a server the bot is in.
discord.replied
Someone replies to your message without mentioning you.
Good to know

Reads through a bot of your own, so it sees only the servers you add it to, and never your DMs. Each server continues from its own saved cursor.

Watch less, with Discord search parameters --filter 'author_type=-bot'

Jira

jira.commented
Someone comments on an issue you are assigned to, reported or watch.
jira.mentioned
A comment @mentions you.
jira.transitioned
The status changes, like To Do to Done.
jira.assigned
Someone assigns the issue to you.
Good to know

Skips your own actions and continues from a cursor saved in ~/.local/state/hark.

Watch less, with JQL --filter 'project = PROJ AND priority = High'

Linear

linear.mentioned
Someone mentions you in an issue or a comment.
linear.assigned
Someone assigns an issue to you.
linear.commented
Someone comments on an issue you are subscribed to.
linear.transitioned
The status changes, with the status it has now.
Good to know

Reads your Linear inbox, archived notifications included, and continues from a saved cursor. Other notifications show up as linear.<type>.

Watch less, with a Linear notification filter --filter '{"type":{"eq":"issueMention"}}'

Datadog

datadog.alert
A monitor, or one group of a multi alert monitor, goes into Alert.
datadog.warndatadog.no_data
It goes into Warn or No Data.
datadog.recovered
It goes back to OK.
Good to know

Reads the monitor alerts of the whole organization, so filter it down to what you own. Skips re-notifications and continues from a saved cursor.

Watch less, with Datadog event search --filter 'team:payments -env:staging'

Todoist

task.createdtask.completed
A task is added or completed, by you or a collaborator.
task.rescheduled
A due date changes, with the new date.
task.commented
Someone comments on a task.
task.due
Once a day, for each task due today.
Good to know

Reads the activity log, so your Todoist plan needs activity history. Continues from a saved cursor.

Frequently asked questions

Something else? Open an issue on GitHub.

Which agents does hark work with?

Claude Code runs hark as a background monitor and reacts to each line it prints. Copilot CLI has no monitor, but it wakes the agent when a background command exits, so the same prompt has it run hark with --exit-on-event, which exits after each batch of events, and start it again. Other agents can run hark in the background too, but they only see new events when they check.

How is this different from an MCP server?

An MCP server answers when the agent asks. hark tells the agent when something happens, without being asked. They work well together: hark says a review arrived, and the agent reads it with gh or an MCP server.

Do I need a server or webhooks?

No. hark runs on your machine and checks each service once a minute with your own tokens. There is nothing to deploy and no account to create.

Where do my tokens go?

Only to the services they belong to. hark reads them from your environment, and the only other place it connects to is GitHub, to look for a newer version of itself.

Can hark change things in my accounts?

hark only reads, except that it marks the GitHub notifications it reports as read. What the agent does is up to the prompt, and the one on this page tells it to ask you before it replies, closes or changes anything.

What happens if a monitor stops?

Your agent starts it again. Every service except GitHub continues from where it stopped, and for GitHub the agent passes the time of the last line to --since, so nothing in between is lost.

Does it work with GitHub Enterprise and Jira Server?

GitHub Enterprise works: set HARK_GITHUB_API to your API URL. Jira needs a Jira Cloud site.

Which systems does it run on?

Linux and macOS, on amd64 and arm64.

How much does it cost?

Nothing. hark is free, and its source is on GitHub.
