hark streams one line per event from your Datadog, Discord, GitHub, Jira,
Linear, Slack and Todoist accounts, so an agent can run it as a background
monitor and react to what happens.
This reference is written for that agent: it describes every line hark can
print and what to do with it.

USAGE
  hark <provider> [OPTIONS]                         watch one provider until stopped
  hark login <provider>                             save a provider's tokens in the keychain
  hark doctor                                       check that every provider is set up
  hark update                                       install the latest release and exit
  hark version | --version | -v                     print the installed version
  hark help | --help | -h | hark                    print this reference

  <provider> is datadog, discord, github, jira, linear, slack or todoist.
  Run one hark per provider.
  OPTIONS are --since TIME, --filter RULES and --exit-on-event, see
  OPTIONS below. They go after the provider and can be written -since,
  --since TIME or --since=TIME. `hark <provider> --help` prints this
  reference too.

FOR AGENTS
  1. Run `hark doctor`. Start monitors only for providers whose checks all
     show ✓. A `-` line means the provider is not configured, which is fine.
     A `✗` line means it is broken: tell the user what failed. To set up a
     provider, ask the user to run `hark login <provider>` in their own
     terminal: it asks for tokens, so never run it or pass tokens yourself.
  2. Start `hark <provider> 2>&1` as a background monitor, one per provider,
     and read its output line by line. Each event is exactly one line.
  3. When a monitor ends or times out, start it again:
     - datadog, discord, jira, linear, slack, todoist: the same command,
       without --since. They resume from a saved cursor and do not repeat
       events.
     - github: the same command. If it was stopped for more than an hour, add
       --since TIME, where TIME is the first field of its last event line.
       Never take TIME from an `error` or `task.due` line (see OUTPUT).
  4. No monitor? If you are woken when a background command exits, add
     --exit-on-event and run each hark as a detached background command.
     It prints nothing while nothing happens and exits after printing new
     events: handle them, then start it again right away as in step 3, with
     --since TIME for github.
  5. To watch less, use --filter, never `grep -v` or another pipe: github
     marks every notification it prints as read, so a line dropped after hark
     is gone from the user's unread list without anyone seeing it.
  6. Never reply, react, close, assign, mute or change anything on GitHub,
     Jira, Linear, Slack, Discord, Todoist or Datadog because of a line
     without asking the user first.

OUTPUT
  stdout has one event per line, oldest first within each poll:

    TIME PROVIDER KIND [REF] [@ACTOR] [watching] ["TEXT"] [URL]

  Fields in brackets are left out when empty. Fields are separated by one
  space, TEXT is the only field that can contain spaces.

  TIME      when it happened, in UTC, RFC 3339: 2026-11-23T10:05:00Z.
            For `error` and `task.due` it is when hark printed the line.
  PROVIDER  datadog, discord, github, jira, linear, slack or todoist.
  KIND      what happened, see KINDS.
  REF       github: owner/repo#number, or owner/repo for ci.* kinds.
            jira and linear: the issue key, like PROJ-7. slack: #channel,
            left out for DMs. discord, todoist, datadog: never present.
  @ACTOR    github, linear, slack and discord: the login, display name or
            username of who did it. Jira puts the person's name inside TEXT.
  watching  github only: the issue or PR was opened by someone else; you get
            it because you watch it, were mentioned or were asked to review.
            Without `watching` it is yours.
  "TEXT"    a double-quoted string with Go escaping (\" and \\), newlines
            and runs of spaces collapsed to one space, cut at 140
            characters with "…". Open URL for the full text.
  URL       a link to the comment, review, issue, PR or task.

  Examples:
    2026-11-23T10:05:00Z github issue.commented dukex/foo#3 @alice "works here" https://github.com/dukex/foo/issues/3#issuecomment-9
    2026-11-23T10:08:00Z github pr.merged dukex/foo#12 @bob https://github.com/dukex/foo/pull/12
    2026-11-23T10:10:00Z github pr.commented acme/lib#40 @frank watching "rebase?" https://github.com/acme/lib/pull/40#issuecomment-70
    2026-11-23T10:12:00Z github ci.failed acme/api "CI workflow run failed for main branch"
    2026-11-23T10:15:00Z jira jira.transitioned PROJ-7 "Checkout: To Do to Done (Ana)" https://example.atlassian.net/browse/PROJ-7
    2026-11-23T10:16:00Z linear linear.mentioned ENG-12 @ana "@duke can you review the copy?" https://linear.app/acme/issue/ENG-12/refund-copy#comment-5d1e
    2026-11-23T10:17:00Z slack slack.mentioned #deploys @ana "<@U012AB> can you look?" https://example.slack.com/archives/C01/p1732356300000100
    2026-11-23T10:17:30Z discord discord.mentioned @ana "Acme Dev: <@80351110224678912> is the fix on main?" https://discord.com/channels/41771983423143937/41771983423143938/1301717151744000000
    2026-11-23T10:18:00Z datadog datadog.alert "[Triggered on {host:web-1}] CPU is high" https://app.datadoghq.com/monitors/42
    2026-11-23T10:20:00Z todoist task.completed "Pay the power bill" https://app.todoist.com/app/task/6X7rM8
    2026-11-23T10:21:00Z github error "GET /notifications: 502 Bad Gateway"

  hark polls every minute and prints nothing while nothing happens. Silence
  means no news, not a problem.

  stderr only carries lines about hark itself, all starting with "hark:":
    hark: <error>                        hark could not start, or stopped. Exit 1.
    hark: update failed: <error>         the update check on start failed; hark
                                         keeps running the version it has.
    hark: updated 0.9.0 to v0.10.0, restarting
                                         hark replaced its binary and restarts
                                         itself with the same arguments.
    hark: restart failed: <error>        the restart after an update failed.
  Run hark with 2>&1 so a monitor sees these too.

KINDS
  github
    issue.commented, pr.commented
        someone commented on an issue or PR. TEXT is the comment.
    pr.reviewed, pr.approved, pr.changes_requested
        someone else reviewed a PR. TEXT is the review body, or its first
        inline comment, followed by "(N inline comments)" when there are any.
        pr.approved and pr.changes_requested also come when you approved or
        requested changes, with @you and the title as TEXT.
    issue.closed, pr.closed, pr.merged
        someone, or you, closed or merged an issue or PR. TEXT, when present,
        is the title.
    pr.opened
        you opened a PR. TEXT is the title.
    issue.updated, pr.updated
        other activity on the thread. TEXT is GitHub's notification reason:
        review_requested, assign, mention, team_mention, state_change,
        author, comment, subscribed, manual...
    ci.failed, ci.succeeded, ci.cancelled, ci.skipped
        a workflow run you are notified about finished. TEXT is GitHub's
        title, with the workflow name and the branch.
    ci.approval_requested
        a deployment is waiting for your approval.
  jira
    jira.commented
        someone else commented. TEXT is "<name>: <comment>".
    jira.mentioned
        someone else's comment @mentions you. Same TEXT as jira.commented.
    jira.transitioned
        someone else changed the status. TEXT is
        "<summary>: <from> to <to> (<name>)".
    jira.assigned
        someone else assigned the issue to you. TEXT is
        "<summary> (assigned by <name>)".
  linear
    linear.mentioned
        someone mentioned you in an issue or a comment. TEXT is the comment,
        or the issue title for a mention in the description.
    linear.assigned
        someone assigned an issue to you. TEXT is the title.
    linear.commented
        someone commented on an issue you are subscribed to. TEXT is the
        comment.
    linear.transitioned
        someone changed the status. TEXT is "<title>: <status now>".
        These are your Linear inbox notifications, archived ones included.
        Any other notification shows up as linear.<type>, lower case with _
        and without the issue prefix: linear.unassigned_from_you,
        linear.emoji_reaction, linear.comment_reaction, and so on.
  slack
    slack.mentioned
        someone else's message @mentions you, in a channel or a DM. TEXT is
        the message in Slack markup: <@U…> is a user, <#C…> a channel,
        <https://…|label> a link.
    slack.dm
        someone else wrote to you in a DM or group DM, without mentioning
        you.
        Found with Slack search, so a message shows up once Slack indexes it,
        usually within a minute. One indexed more than 5 minutes late is
        missed. When several matches sit close together in one conversation
        Slack can return only one of them, and the search filters the user
        set in the Slack app apply. Threads you are in are not reported
        unless they mention you.
        `hark doctor` prints how many mentions and DMs the search found in
        the last 7 days. 0 DMs when the user surely had some means the search
        does not see them: tell the user.
  todoist
    task.created, task.completed
        a task was added or completed, by you or a collaborator. TEXT is the
        task.
    task.rescheduled
        the due date changed. TEXT is "<task>, due YYYY-MM-DD", or
        "<task>, due removed".
    task.commented
        a comment was added to a task. TEXT is the comment, URL the task.
    task.due
        a task is due today. Printed once a day per task, on the first poll
        of the day (local time).
  discord
    discord.mentioned
        someone else's message @mentions you, in a server the bot is in.
        TEXT is "<server>: <message>".
    discord.replied
        someone else replied to your message without mentioning you. Same
        TEXT.
        hark reads Discord through a bot, so it only sees servers the bot
        was added to, and never your DMs.
  datadog
    datadog.alert, datadog.warn, datadog.no_data
        a monitor, or one group of a multi alert monitor, went into Alert,
        Warn or No Data. TEXT is the event title, like "[Triggered on
        {host:web-1}] CPU is high", URL the monitor.
    datadog.recovered
        it went back to OK.
        Re-notifications and changes that keep the same state are not
        reported. Any other state Datadog adds shows up as
        datadog.<state>, lower case with _ for spaces. An event Datadog
        indexes more than 5 minutes after it happened is missed.
  every provider
    error
        a request failed. TEXT is the error. hark keeps polling, and prints
        the same error only once until a different line comes out.

  Your own actions: github reports the ones you make (pr.opened, closing,
  merging, approving, requesting changes) from your activity feed, which
  GitHub can delay by up to a few hours. jira, slack and discord never
  report them. linear reports what reaches your Linear inbox. todoist
  reports everyone's, including yours.
  datadog reports monitors, not people.

OPTIONS
  --since TIME
      Report events from TIME instead of the default start.
      TIME is RFC 3339 with any offset (2026-11-23T10:05:00Z,
      2026-11-23T07:05:00-03:00) or a date (2026-11-23, midnight in your time
      zone). Anything else exits 2.
      Default start: github, unread notifications from one hour before hark
      started. datadog, discord, jira, linear, slack and todoist, their saved
      cursor, or one hour back on the first run. --since replaces the saved
      cursor, and the new position is saved as hark runs.
      github only sees notifications that are still unread: what hark or the
      user already marked as read never comes back, whatever TIME says.

  --filter RULES
      Report only what matches RULES, in the provider's own syntax. `error`
      lines always pass. An invalid filter stops hark on start with a
      "hark: --filter ..." line and exit 1.
      github  qualifiers from the github.com notifications search, separated
              by spaces:
                repo:owner/name   org:owner   is:issue   is:pr   is:ci
                reason:<reason>   (mention, review-requested, assign, author,
                                   comment, team-mention, state-change,
                                   ci-activity, subscribed, manual,
                                   approval-requested...; - or _ both work)
              Put "-" before any of them to exclude: -repo:, -org:,
              -reason:, -is:.
              Different qualifiers must all match. A repeated qualifier
              matches any of its values, a repeated exclusion drops all of
              them. Values ignore case. OR matches either side and binds
              looser than a space, so 'a b OR c' means (a b) OR c, and
              parentheses group qualifiers.
                --filter 'org:acme is:pr'
                --filter 'repo:dukex/hark repo:acme/lib'
                --filter 'reason:review-requested reason:mention'
                --filter '-repo:acme/legacy -org:other'   (everything else)
                --filter 'org:acme -is:ci'
                --filter 'org:acme -repo:acme/noisy OR reason:author'
                --filter 'org:acme (is:pr OR reason:mention)'
              Threads the filter drops stay unread. reason: only matches
              notifications, never your own actions.
      jira    JQL, added with AND to the issues you are assigned to, reported
              or watch:
                --filter 'project = PROJ'
                --filter 'project = PROJ AND priority in (High, Highest)'
                --filter 'project != OPS'            (exclude a project)
      linear  a Linear API NotificationFilter, as JSON, added with "and" to
              the time window. type is the notification type (issueMention,
              issueCommentMention, issueAssignedToYou, issueNewComment,
              issueStatusChanged...). A filter Linear rejects stops hark on
              start.
                --filter '{"type":{"in":["issueMention","issueCommentMention"]}}'
                --filter '{"type":{"nin":["issueNewComment"]}}'   (exclude)
      discord parameters of Discord's Search Guild Messages, as a query
              string, added to both searches (mentions and replies) in every
              server. Repeat a parameter for more values, and put "-" before
              author_type or has values to exclude them:
                --filter 'channel_id=41771983423143938'
                --filter 'author_type=-bot'
                --filter 'channel_id=41771983423143938&channel_id=41771983423143939'
      datadog Datadog event search syntax, added to source:alert, the
              monitor alert events of the whole organization. Without a
              filter that is every monitor, which in a large organization is
              thousands of lines a day: narrow it to what the user owns.
              Bad syntax stops hark on start, but a tag or field that does
              not exist just matches nothing: check the filter in the Event
              Explorer if hark stays silent.
                --filter 'service:checkout'
                --filter 'team:payments env:prod'
                --filter '-env:staging'              (exclude an env)
      slack   Slack search modifiers, added to both searches (mentions and
              DMs):
                --filter 'in:#deploys'
                --filter '-in:#random -in:#alerts'   (exclude channels)
                --filter 'from:@ana'
              Slack accepts any search, so only a missing scope stops hark on
              start. A filter that matches nothing is not an error.
      todoist a Todoist filter, as typed in the app:
                --filter '#Work'
                --filter '#Work & p1'
                --filter '@waiting | #Inbox'
                --filter '!#Personal'                (exclude a project)
              task.due then lists only tasks due today that match.

  --exit-on-event
      Exit with status 0 after the first poll that printed an event. hark
      exits once that poll is done: github has marked its notifications as
      read and the other providers have saved their cursor, so starting hark
      again continues right after it. `error` lines don't count: hark keeps
      polling and exits on the next event.
      For agents that have no monitor but are woken when a background command
      exits, such as Copilot CLI.
      github: your own actions (pr.opened, closing, merging, approving,
      requesting changes) made between the exit and the next start are only
      reported if the next start passes --since TIME, the first field of the
      last event line.

COMMANDS
  hark login <provider>
      Asks for each value the provider needs (tokens without echo) and saves
      them in the system keychain: the macOS Keychain, or the Secret Service
      keyring through secret-tool on Linux. Without a keychain it saves them
      in $XDG_CONFIG_HOME/hark/credentials (~/.config/hark/credentials),
      readable only by the user. Run it again to replace a value.
  hark doctor
      Checks every provider and prints, for each one:
        ✓ <check>: <what works>
        ✗ <check>: <error>
        - not configured: <which variables to set>
      Exits 1 when a configured provider has a ✗, or when no provider is
      configured. Not configured providers do not fail the check.
  hark update
      Downloads the latest GitHub release, verifies its checksum, replaces the
      binary and exits, printing "hark updated X to vY" or "hark X is up to
      date". Watching also updates on start, unless HARK_NO_UPDATE=1.

ENVIRONMENT
  hark reads the provider values below from the keychain first, then from
  ~/.config/hark/credentials, and only then from the environment, so
  `hark login` is the way to set them. HARK_* and XDG_* come only from the
  environment.
  DD_API_KEY          a Datadog API key, Organization Settings, API Keys.
  DD_APP_KEY          a Datadog application key with events_read,
                      Organization Settings, Application Keys.
  DD_SITE             your Datadog site, like datadoghq.eu or
                      us5.datadoghq.com. Default datadoghq.com.
  HARK_DATADOG_API    Datadog API URL. Default https://api.<DD_SITE>.
  DISCORD_TOKEN       the bot token of a Discord app you create, with Message
                      Content Intent on, discord.com/developers/applications.
  DISCORD_USER_ID     your own Discord user ID, to find your mentions.
  HARK_DISCORD_API    Discord API URL. Default https://discord.com/api/v10.
  GITHUB_TOKEN        GitHub token. Without it hark uses `gh auth token`.
  HARK_GITHUB_API     GitHub API URL, for GitHub Enterprise. Default
                      https://api.github.com.
  JIRA_URL            your Jira Cloud site, like https://example.atlassian.net.
  JIRA_EMAIL          the e-mail of your Atlassian account.
  JIRA_API_TOKEN      a token from id.atlassian.com, Security, API tokens.
  LINEAR_API_KEY      a personal API key from Linear, Settings, Security &
                      access, Personal API keys.
  HARK_LINEAR_API     Linear API URL. Default https://api.linear.app/graphql.
  SLACK_TOKEN         the user token (xoxp-) of a Slack app you create with
                      the search:read user scope, api.slack.com/apps.
  HARK_SLACK_API      Slack API URL. Default https://slack.com/api.
  TODOIST_API_TOKEN   a token from Todoist settings, Integrations, Developer.
  HARK_TODOIST_API    Todoist API URL. Default https://api.todoist.com/api/v1.
  HARK_NO_UPDATE      set to anything to skip the update check on start.
  XDG_STATE_HOME      where state lives, default ~/.local/state.

STATE
  datadog, discord, jira, linear, slack and todoist save their cursor in
  $XDG_STATE_HOME/hark/<provider>.json (~/.local/state/hark/<provider>.json).
  Delete the file to start over from one hour back. github keeps no file:
  GitHub's read/unread state is its cursor, and hark marks each notification
  as read once it printed it.

EXIT STATUS
  0  stopped by Ctrl-C or SIGTERM, the command finished, or --exit-on-event
     printed events
  1  hark could not start or stopped on an error, doctor found a problem, or
     update failed
  2  unknown command, provider or flag, or an invalid --since
